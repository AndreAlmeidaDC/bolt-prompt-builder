# Seleção atual de plataforma

A escolha depende do projeto e deve ser revalidada nas documentações oficiais. Nenhuma plataforma fica congelada no arquétipo de seu lançamento.

| Plataforma | Use quando | Principal cuidado |
|---|---|---|
| Lovable | app web ou site experiencial com fluxo guiado, knowledge, planejamento e backend opcional | não delegar direção de marca nem publicar sem revisão |
| v0 | app full-stack ou UI em ecossistema React/Next.js, Git-first, Vercel e sandbox | permissões do terminal, integração e produção |
| Bolt | web ou Expo com execução JavaScript, Bolt Database ou Supabase | compatibilidade do ambiente, backend escolhido e consumo de tokens |
| Base44 | app gerenciado, automações, entidades, agentes e connectors com desenvolvimento rápido | dependência das semânticas e serviços gerenciados; planejar saída |
| Emergent | execução agentic de produtos web/mobile com ciclos mais autônomos | custo, convergência, modelo/agente e revisão do código produzido |
| a0 | produto mobile-first com build, OTA e publicação iOS/Android | runtime, permissões, testes nativos e regras das stores |

## Perguntas decisivas

1. Existe repositório e stack a preservar?
2. Precisa de web, mobile ou ambos?
3. Precisa de backend agora?
4. Quem controla código, dados, infraestrutura e saída?
5. Há credenciais, pagamentos, produção ou dados regulados?
6. O diferencial é produto, direção visual, automação ou velocidade?
7. Quais testes e caminhos de rollback a plataforma permite?

Escolha a ferramenta que reduz o risco dominante. Não escolha por uma tabela histórica de features ou preço.
